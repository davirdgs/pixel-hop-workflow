# Workflow: spec-status

1. Follow `_common.md`; read persisted metadata, tasks, coverage dispositions, validation, evidence, and active claims.
2. Derive status rather than trusting legacy `phase` alone.
3. If lifecycle phase is `closed`, report closure reason, provenance, prior phase, optional successor, and that no implementation/validation action remains. Do not recommend repairing or completing historical artifacts.
4. Otherwise report artifact approvals/hash validity, task completion, implementation/validation state, blockers, claims, and the next legal transition.
5. This workflow is read-only.
